Command Line Options Reference

The following reference matches the Snug command-line help used for this edition of the book. For the definitive options supported by your installed version, run snug.exe --help.

This section is intended as a quick lookup reference. For explanations, examples, and guidance on when to use each option, see Section 4: Configuration Options.

Quick Overview

Option(s)

Notes

Minimum Input Required for a Normal Build

--input <JAR|DIR>

or

[JAR|DIR]

Input source: either a single JAR or a directory containing JAR files.

Positional alternative to --input. The two forms are mutually exclusive.

Application Identity

--name <NAME>

Application display name. Used in Windows metadata and Snug's per-user application identity.

--company <COMPANY>

Company or vendor name. Used in Windows metadata and Snug's per-user application identity.

Output

-o, --output <EXE>

Output Windows executable path. If omitted for a single-JAR build, Snug uses the JAR filename as the basis for the .exe name.

Application Metadata

--version <VERSION>

Application version. Accepts one to four numeric components, each from 0 to 65535. Missing trailing components default to zero.

--description <TEXT>

Windows FileDescription metadata.

--copyright <TEXT>

Windows LegalCopyright metadata.

--update-url <URL>

Adds a clickable "Check for a newer version" link to launcher error dialogs.

--icon <PNG/ICO>

PNG or ICO file used as the Windows executable icon.

Java Runtime

--min-java <N>

Minimum required Java major version. Default: 25.

--main-class <CLASS>

Overrides the Main-Class read from the JAR manifest.

--jvm-arg <OPTION>

Extra JVM option passed when the JVM is created. Repeatable.

Windows Resources

--manifest <XML>

Windows application manifest embedded as RT_MANIFEST.

--splash <PNG>

PNG splash image shown by the native launcher before the JVM starts.

--splash-ms <MS>

Minimum splash duration in milliseconds. Default: 1500.

--splash-max <WxH|off>

Recommended maximum splash dimensions used for a build-time warning. Default: 640x360. The setting does not resize the image.

Runtime Behaviour and Localisation

--download-jdk[=off|auto|force]

Controls Snug's managed Java-runtime download behaviour. Default: auto.

Unless you have a specific requirement you shouldn't use the value off as this will lead to the application being unable to  start if no JVM is installed on the local Windows machine.

--localisation <TXT|DIR>

Embeds launcher localisation bundles. May be repeated for individual files or supplied with a directory containing snug-localisations.<tag>.txt files.

--allow-multiple-instances

Allows more than one copy of the packaged application to run at the same time. By default, Snug applications are single-instance.

Build and Diagnostic Tools

--dry-run

Validates inputs and reports what would be built without writing an executable.

--find-main

Lists classes in the input JAR or JARs that declare public static void main(String[]) and identifies the main class Snug would use when applicable.

--emit-payload

Writes the encoded embedded payload to standard output instead of building an executable.

Snug Tooling Options

--snug-version

Prints Snug's own version and exits.

--options <PATH>

Selects an options file. By default Snug looks for snug.options in the current working directory.

--init-options [<PATH>]

Writes Snug's embedded example options file and exits. If no path is supplied, the default is ./snug.options.

--init-options-force

Allows --init-options to overwrite an existing destination file.

--init-options-stdout

Prints the example options configuration to standard output instead of writing a file.

-h, --help

Prints Snug's command-line help.

Notes on the 'Importance' designator of command line options

The 'Importance' of the command line option will have one of three values:

  • Required - this command line option is required or Snug will fail to package the application and return an error
  • Recommended - this command line option is recommended to be set, whilst the build will not fail, there may be some unforeseen outcomes if not set
  • Optional - this command line option may already have a default set, or will not impact the building or running of the Snug packaged application

Notes on the 'Repeatability' designator of command line options

The 'Repeatability' designator shows whether this option may be included on the command line or in the snug.options file either a single time, or multiple times.  It will be one of two values:

  • Single - this option may be included at most once
  • Multiple - this option may be included zero, one, or as many times as is required

Notes on the 'Where to Use' designator of command line options

The 'Where to Use' designator will be one of three values

  • Options - This option is only available to be placed in the snug.options file
  • CLI only - This option is only available through the command line.  If this option is placed in the snug.options file the build will error and exit.
  • Both - This option may be placed in the snug.options file or on the command line.  Note: If used in both places, the command line option will take precedence and be used.

Snug Builder (snug.exe) Options Reference

--input

Required

Selects the JAR file or directory of JAR files that Snug should package.

Single

Both

Syntax

Showing the syntax - the option parameter and the value (if any)

When to use

Use it when you want the input source to be explicit, especially in the  snug.options file.

If omitted

ERROR - Packaging fails. On the command line you may use the positional [JAR|DIR] input instead. An options file still requires --input., the positional input is good for quick testing but it is highly recommended to place it in the snug.options file.

Example

--input build\libs\my-app.jar

Important note

The positional [JAR|DIR] form works only on the command line and cannot be placed in snug.options.

--name

Required

Sets the company or vendor name for Windows application identity.

Single

Both

Syntax

--name <NAME>

When to use

Always set this to the real application name for a normal build.

If omitted

ERROR - Packaging fails. A normal application build cannot be completed because Snug needs the application identity.

Example

--name "My Application Name"

Important note

Together with --company, this value affects what Snug presents to windows as the application name.

--company

Required

Sets the company or vendor name for Windows application identity.

Single

Both

Syntax

--company <COMPANY>

When to use

Always set this to the real company or vendor name for a normal build.

If omitted

ERROR - Packaging fails. A normal application build cannot be completed because Snug needs the application identity.

Example

--company "My Company"

Important note

Together with --name, this value affects what Snug presents to windows as the application name.

-o, --output

Recommended

Sets the company or vendor name Windows application identity.

Single

Both

Syntax

--output <EXE>

When to use

Use it when you want to control the output filename or location.

If omitted

Snug chooses the default output name for the build.

Example

--version

Recommended

Sets the Windows version number for the application identity.

Single

Both

Syntax

--version <VERSION>

When to use

If omitted

Example

The version may contain one to four numeric components, each from 0 to 65535.

--description

Recommended

Sets the Windows FileDescription metadata.

Single

Both

Syntax

--description <TEXT>

Use it to give the executable a meaningful description in Windows properties.

If omitted

Windows receives no custom FileDescription from this option.

Example

--description "Invoice Viewer"

Important note

This affects metadata only; it does not change the application's display name.

--copyright

Optional

Sets the Windows LegalCopyright metadata for the application identity.

Single

Both

Syntax

--copyright <TEXT>

When to use

Use it when you want copyright information embedded in the executable.

If omitted

No custom LegalCopyright value is supplied.

Example

--description "Invoice Viewer"

Important note

This is informational metadata and does not provide legal protection by itself.

Single

Both

Syntax

--update-url <URL>

If omitted

Launcher dialogs do not include an update link.

Example

--update-url https://example.com/downloads

--icon

Optional

Sets the icon embedded in the application executable.

Single

Both

Syntax

--icon <PNG/ICO>

When to use

Use it for a branded application icon.

If omitted

The default Snug application icon is used.

--min-java

Optional

Sets the minimum Java major version required by the application.

Single

Both

Syntax

--min-java <N>

When to use

Use it when the application requires a Java version different from the default.

If omitted

Snug will set the minimum Java version to Java 25.

Example

--min-java 25

Important note

Choose the lowest Java major version that the application genuinely requires.

--main-class

Optional

Overrides the Main-Class that Snug would otherwise use in the manifest.

Single

Both

Syntax

--main-class <CLASS>

When to use

Use it when discovery is ambiguous or you intentionally want a different entry point.

If omitted

Snug uses its normal main-class detection behaviour.

Example

--main-class com.example.Launcher

Important note

The class must be a valid application entry point available in the packaged JARs.

At snug packaging time, you may use the option --find-main to look through the JAR file(s) to find and confirm which main class will be used.

--jvm-arg

Optional

Passes an option directly to the JVM when Snug creates it.

Multiple

Both

Syntax

--jvm-arg <OPTION>

When to use

Use it only when the Java application requires a specific JVM option, such as a memory limit or system property.

If omitted

The JVM starts without any additional options supplied by Snug.

Example

--jvm-arg=-Xmx2g

Important note

Invalid or unsupported JVM arguments can prevent the Java runtime from starting.

--manifest

Optional

Embeds a Windows application manifest as RT_MANIFEST.

Single

Both

Syntax

--manifest <XML>

When to use

Use it only when the application needs a custom Windows manifest.

If omitted

No custom manifest file is embedded[a].

Example

--manifest snug\app.manifest

Important note

Snug includes the manifest as supplied; it does not inspect, parse, or validate it.

--splash

Optional

Sets the PNG splash image shown by the launcher before the JVM starts.

Single

Both

Syntax

--splash <PNG>

When to use

Use it when you want a branded launcher splash while Java starts.

If omitted

The launcher starts without the custom splash image.

Example

--splash snug\splash.png

Important note

This is the Snug launcher splash, separate from JVM or JavaFX splash mechanisms.

--splash-ms

Optional

Sets the minimum time the Snug splash remains visible.

Single

Both

Syntax

--splash-ms <MS>

When to use

Use it when the splash should remain visible for at least a specific duration.

If omitted

Snug uses the default minimum duration of 1500 ms - i.e. 1.5 seconds.

Example

--splash-ms 2000

Important note

This is a minimum duration, not a guarantee that the startup will finish at that time.

--splash-max

Optional

Sets the recommended maximum splash dimensions used for a build-time warning.

Single

Both

Syntax

--splash-max <WxH|off>

When to use

Use it to change or disable the splash-size warning threshold.

If omitted

Snug uses the default 640x360 recommendation.

Example

--splash-max 800x450

Important note

This option does not resize the image; it only controls the build-time warning.

This will not stop the packaging, it will just present an error.

--download-jdk

Optional

Controls Snug's managed Java-runtime download behaviour.

Single

Both

Syntax

--download-jdk[=off|auto|force]

When to use

When you want to control whether Snug downloads a JDK.  Normally leave this at the default of auto. Use force for testing or when you deliberately want the managed runtime path.

If omitted

Snug uses automatic runtime discovery and download behaviour - i.e. the value is set to auto.

Example

--download-jdk=force

Important note

Using off can leave the application unable to start on a machine without a compatible Java runtime.

--localisation

Optional

Embeds launcher localisation bundles.

Single

Both

Syntax

--localisation <TXT|DIR>

When to use

Use it to add translated or customised launcher messages.

If omitted

Only the built-in English launcher messages are available.

Example

--localisation snug\localisation

Important note

Both spellings are accepted. Files may be supplied individually, or a directory may contain snug-localisations.<tag>.txt[b] files.

--allow-multiple-instances

Optional

Allows more than one copy of the application to run at the same time.

Single

Both

Syntax

--allow-multiple-instances

When to use

Use it only when separate simultaneous copies of the application are genuinely useful.

If omitted

If the application is already running, Snug activates the existing instance instead of starting another copy.

Example

--allow-multiple-instances

Important note

For most desktop and business applications, leaving the default single-instance behaviour in place is simpler for users.

--dry-run

Optional

Single

CLI[c] only

Syntax

--dry-run

When to use

Use it to check configuration before performing a real build.

If omitted

Snug performs the normal build.

Example

--dry-run

Important note

This is a diagnostic build command and is best used directly from the command line.

--find-main

Single

--find-main

--find-main

--options

Optional

Single

CLI only

When to use

Example

Important note

Command-line values still take precedence over values loaded from the options file.

--init-options

Optional

Writes Snug's embedded example options file and exits.

Single

CLI only

When to use

Use it to create a starter[g] options file. (./snug.options)

If omitted

Example

--init-options-force

Optional

Allows --init-options to overwrite an existing destination file.

Single

CLI only

Syntax

--init-options-force

When to use

Use it only with --init-options when replacing an existing options file is intentional.

If omitted

Snug protects an existing destination from being overwritten by --init-options.

Example

Important note

This option is deliberately explicit because overwriting[h] an options file can discard local configuration.

--init-options-stdout

Optional

Single

CLI only

Syntax

--init-options-stdout

Example

Important note

This is useful for scripting or comparing the embedded example configuration with an existing file.

--cache-dir

Optional

Overrides the application's default per-user cache location.

Single

Both

Syntax

--cache-dir <ABSOLUTE_DIR>

When to use

Only when a deployment has a compelling storage requirement.

If omitted

Snug uses its normal per-user cache location -  %LOCALAPPDATA%\snug\

Example

--cache-dir "D:\\ApplicationCache"

Important note

Not recommended for normal distribution. The[j] path is embedded at build time and may be missing or unwritable on another computer.

--init-localisations

Optional

Creates starter localisation files and exits without building an application.

Single

CLI Only

Syntax

--init-localisations [DIR]

When to use

To create English message files and optional translation templates[k].

If omitted

No localisation files are generated.

Example

--init-localisations

Important note

The built-in English baseline is generated; use --init-localisations-tag to add language templates. CLI spelling will also accept the American English -izations.

--init-localisations-tag

Optional

Adds a language template when generating localisation files.

Single

CLI Only

Syntax

--init-localisations-tag <TAG>

When to use

With --init-localisations, to scaffold additional language files.

If omitted

Only the English baseline[l] is generated.

Example

--init-localisations --init-localisations-tag de

Important note

Templates initially contain English values; translating them is a separate step.

--init-localisations-force

Optional

Adds a language template when generating localisation files.

Single

CLI Only

Syntax

--init-localisations-force

When to use

Only when deliberately replacing previously generated translation files.

If omitted

Existing files remain protected from overwrite.

Example

--init-localisations --init-localisations-force

Important note

Overwriting files can discard customised translations.

--init-localisations-stdout

Optional

Prints generated localisation templates to standard output.

Single

CLI Only

Syntax

--init-localisations-stdout

When to use

For inspection, scripting, or piping generated message templates.

If omitted

Templates are written to the selected directory.

Example

--init-localisations --init-localisations-stdout

Important note

This is a scaffolding command and does not package an application.

Snug Preview (snug_preview.exe) Options Reference

Optional

Single

CLI Only
