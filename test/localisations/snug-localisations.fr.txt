# ============================================================================
#  snug-localisations.fr.txt - French bundle
# ============================================================================
#
#  This file is the French translation of every runtime string the Windows
#  launcher emits. It is not embedded by default -- pass it on the build
#  line with `--localization` -- and a machine whose UI language resolves
#  to `fr` picks it up automatically, falling back to the built-in
#  English baseline for any key this file does not define.
#
#  Format
#  ------
#    key = value                # one entry per line
#    # comment                  # anything after `#` is ignored
#                                # blank lines are ignored too
#
#    value-side escapes:
#      \n  newline
#      \t  tab
#      \r  carriage return
#      \\  literal backslash
#      \#  literal hash (so you can put one in a value)
#      \=  literal equals
#
#    placeholder syntax (filled at lookup time):
#      {name}  replaced with the named value the caller passes.
#              Format specifiers like {name:.2} are NOT supported - apply
#              them to the value in Rust before calling.
#              Unknown placeholders are left as-is so a typo doesn't
#              silently swallow text.
#
#  File naming
#  -----------
#    The locale tag (the part after the last `.` in the filename) is
#    parsed by the launcher at runtime: `snug-localisations.en.txt` is the
#    primary English tag, `snug-localisations.en-US.txt` is the US regional
#    variant (overrides keys on top of `en`). Regional tags fall back to
#    the primary subtag when the user's Windows UI language is `en-GB`,
#    `en-AU`, etc.
#
#  Adding a new language
#  ---------------------
#    1. Copy this file to `snug-localisations.<your-tag>.txt` (e.g.
#       `snug-localisations.de.txt`, `snug-localisations.fr.txt`).
#    2. Translate every `value` field. Keep the keys identical - the
#       launcher matches on key, not on line order.
#    3. Pass it on the build line:  `snug app.jar --localization de.txt -o App.exe`
#       (repeat `--localization` for multiple languages).
#    4. The CLI warns at build time about any keys you missed compared
#       to this English baseline - keep the list in sync.
#
#    Overriding only some keys in a regional variant is fine: keys you
#    don't override fall through to the primary subtag and then to `en`,
#    so you can ship `pt-BR.txt` with three changes on top of `pt.txt`
#    without duplicating the whole bundle.
# ============================================================================

# ----------------------------------------------------------------------------
# Dialog chrome - the download / install / retry windows
# ----------------------------------------------------------------------------
# Titles, headings, subheadings, info-box copy and button labels for every
# custom-painted window the launcher shows. These live here rather than in a
# separate `dialogs.toml` so a `--localization <tag>` bundle translates the
# whole window, not just the error text inside it.
#
# `snug_launcher::dialogs::Dialogs` is hand-assembled from these keys rather
# than deserialized from a file, so the typed struct and its compile-checked
# accessors (`dialogs().runtime.prompt.title`) survive the merge - only
# the source of the strings moved. The practical consequence for you: a
# localised app can now reword the chrome as well as the errors, e.g. "Acme
# requires Java 25" instead of "Eclipse Temurin JDK was not found".
#
# Escaping reminder: these are single-line values. Real newlines are literal
# `\n`; a literal `#` in a value must be written `\#`.
